# 5. Interfaces Folder Specification

The `interfaces/` directory contains all **platform communication adapters** — the bridges between external messaging platforms (Telegram, Discord) and the Meridian agent core. Files here handle incoming signals and outgoing notifications/reports. They contain **no trading or agent business logic**.

> [!IMPORTANT]
> **Folder Behavior & Philosophy:**
> 1. **The Gate File Rule (Outbound)**: `interfaces/index.ts` is the **only file** imported from outside this folder for sending messages. The main loop, `core/`, and `llm/` must never call `telegram/index.ts` directly. All outbound notifications go through the gate — which ensures consistent message format and routes to the correct active platform(s).
> 2. **No Direct Tool Calls**: Interfaces must not call trading tools (deploy, close, claim) directly. All user-initiated actions are routed to the LLM agent loop (`llm/agent.ts`) which evaluates intent and executes the appropriate tool chain.
> 3. **Security at the Edge**: Authorization checks (allowed user IDs, allowed chat IDs) are enforced at the platform level — before any message reaches the agent loop. This is the first and only place where user identity is validated.
> 4. **Inbound has no gate**: Inbound signal ingestion (Discord signals) is platform-specific and feeds directly into `llm/agent.ts`. It does not go through `interfaces/index.ts` — that gate is for outbound only.

## Architecture Design: Two Separate Flows

### Outbound — Messages to the User (gated)

```
  index.ts / core/ / llm/
       │
       │  import { notifyDeploy, notifyClose, createLiveMessage, ... }
       │         from "interfaces/index.ts"
       ▼
  ┌──────────────────────────────────────┐
  │        interfaces/index.ts           │  ← Outbound gate
  │  Consistent format, platform routing │
  └──────────────────┬───────────────────┘
                     │
          ┌──────────┴──────────┐
          ▼                     ▼
  telegram/index.ts        (future: slack/, web/)
  Telegram Bot API
```

### Inbound — Signals from Platforms (no gate)

```
  Discord channel
       │
       ▼
  interfaces/discord/index.ts      ← WebSocket listener (input only)
  interfaces/discord/pre-checks.ts ← signal validation pipeline
       │
       ▼
  llm/agent.ts                     ← dispatched directly (no gate needed)

  Telegram user message
       │
       ▼
  telegram/index.ts: startPolling(handler)
       │  handler lives in index.ts (orchestrator)
       ▼
  llm/agent.ts                     ← dispatched via GENERAL role
```

## `interfaces/index.ts` — The Outbound Gate

The gate exposes a **fixed message contract**. All callers use these functions. Platform-specific formatting (HTML, Markdown, chunking) happens inside the platform sub-folder, not at the call site.

### Notification Functions (from real `telegram.ts` exports)

| Function | Trigger | Message sent |
| :--- | :--- | :--- |
| `notifyDeploy({ pair, amountSol, position, tx, priceRange, rangeCoverage, binStep, baseFee })` | Position opened | `✅ Deployed PAIR — Amount, price range, bin step, position addr, tx hash` |
| `notifyClose({ pair, pnlUsd, pnlPct })` | Position closed | `🔒 Closed PAIR — PnL $X.XX (+X.XX%)` |
| `notifySwap({ inputSymbol, outputSymbol, amountIn, amountOut, tx })` | Token swapped | `🔄 Swapped TOKEN → TOKEN — In/Out amounts, tx hash` |
| `notifyOutOfRange({ pair, minutesOOR })` | Position OOR | `⚠️ Out of Range PAIR — X minutes OOR` |

### Messaging Primitives

| Function | Purpose |
| :--- | :--- |
| `sendMessage(text)` | Plain text message, max 4096 chars |
| `sendHTML(html)` | HTML-formatted message (bold, italic, code) |
| `sendLongMessage(text)` | Auto-chunks long text across multiple messages, auto-detects markdown |
| `sendMessageWithButtons(text, inlineKeyboard)` | Message with inline keyboard buttons |
| `editMessage(text, messageId)` | Edit an existing message in place |
| `editMessageWithButtons(text, messageId, inlineKeyboard)` | Edit message + update buttons |
| `sendDocument(filePath, { caption? })` | Send file as Telegram document (VP HTML report, etc.) |
| `answerCallbackQuery(callbackQueryId, text?)` | Acknowledge an inline button press |
| `isEnabled()` | Check if Telegram token is configured |

### Live Message (Agent Progress Tracker)

The live message is a single editable Telegram message that shows real-time agent progress — tool calls update it in place as the agent works.

```ts
const live = await createLiveMessage("🤖 Managing positions", "Starting...");

await live.toolStart("close_position");           // ℹ️ close position ...
await live.toolFinish("close_position", result, true); // ✅ close position — closed
await live.note("Evaluating next position...");   // updates intro text
await live.finalize("Done. Closed 1 position.");  // final message, stops typing
// or:
await live.fail("RPC error — retrying later");    // ❌ error footer
```

| Method | Effect |
| :--- | :--- |
| `createLiveMessage(title, intro)` | Sends initial message, starts typing indicator |
| `.toolStart(name)` | Adds `ℹ️ tool name ...` line |
| `.toolFinish(name, result, success)` | Updates line to `✅/❌ tool name — summary` |
| `.note(text)` | Updates intro text in message body |
| `.finalize(text)` | Sets footer, stops typing indicator |
| `.fail(errorText)` | Sets `❌ error` footer, stops typing |

## Naming Convention — `{functionName}{PlatformName}`

Internal platform functions follow **`{functionName}{PlatformName}`**. This keeps `interfaces/index.ts` routing self-documenting.

```ts
// interfaces/telegram/index.ts
export async function sendMessageTelegram(text: string) { ... }
export async function notifyDeployTelegram(data: DeployData) { ... }

// interfaces/index.ts — routing is readable at a glance
export async function notifyDeploy(data: DeployData) {
  if (telegramEnabled()) await notifyDeployTelegram(data);
  // future: if (slackEnabled()) await notifyDeploySlack(data);
}
```

| Platform suffix | Platform |
| :--- | :--- |
| `Telegram` | Telegram Bot API |
| `Discord` | Discord WebSocket (inbound only) |
| *(future)* `Slack` | Slack Bolt |
| *(future)* `Web` | Web dashboard push |

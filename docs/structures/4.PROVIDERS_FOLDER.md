# 4. External Folder Specification

The `providers/` directory contains all external I/O adapters, third-party API integrations, and blockchain SDK wrappers. Files in this folder are **strictly I/O-only and contain zero trading or agent business logic**.

> [!IMPORTANT]
> **Folder Behavior & Philosophy:**
> 1. **The Barrel Rule**: Provider subdirectories export their public API through `index.ts` barrel files. Code outside `providers/` should import from the barrel (`providers/solana/index.js`), not from internal files like `providers/solana/balance.ts`. The ESLint config enforces this. If a provider gets an official npm package (e.g. `@okx/onchain-sdk`), only the files inside that provider's subfolder change. Nothing outside `providers/` ever knows.
> 2. **Retry within a provider**: For tasks with a single remote source (most of them), the provider file implements transient-error retry with jittered backoff (e.g. `providers/solana/balance.ts` retries Helius 3×). No cross-provider fallback exists today — if Helius is down, wallet balance returns an error.
> 3. **`providers/sdk.ts` is reserved for cross-provider abstractions** that don't fit in any single provider. Currently a stub — populated only when a real multi-provider operation needs a unified facade. The current codebase has no such operation, so `sdk.ts` is intentionally empty.
> 4. **`caller.ts` is the HTTP transport layer**: Handles retry, backoff, and timeout for all providers. It has no knowledge of which provider or what data — purely transport concerns.

```
   core/ · llm/ · interfaces/
        │
        │  import { getWalletBalances } from "providers/solana/index.js"
        │  import { getTokenInfo } from "providers/jupiter/index.js"
        │  import { getTopCandidates } from "providers/meteora/index.js"
        │  import { fetchExitConfirmations } from "providers/hivemind/index.js"
        ▼
  ┌──────────────────────────────────┐
  │  providers/<name>/index.ts        │  ← Barrel: re-exports the public API
  │                                  │
  │  providers/solana/balance.ts      │  ← Helius → RPC fallback lives here

  └──────────────┬───────────────────┘

                 ▼
  ┌──────────────────────────────────┐
  │        providers/caller.ts        │  ← HTTP transport: retry, backoff, timeout
  └──────────────────────────────────┘
```

## Provider Sources — Current State

Each task is bound to a single primary source. Within that source, the provider file implements retry with backoff for transient failures:

| Task | Source | Where retry lives |
| :--- | :--- | :--- |
| Wallet token balances | Helius Enhanced API | `providers/solana/balance.ts` (3× retry with jittered backoff) |
| Token price feed | Jupiter Price API | — |
| Wallet risk score | OKX OnchainOS | — |
| Account reads | Meteora SDK / Solana RPC | direct in `dlmm.ts` via `getConnection()` |
| Tx simulation | Meteora SDK | — |
| Swap execution | Jupiter | — |
| DLMM pool operations | Meteora SDK | — |
| HiveMind sync | Agent Meridian API | — |

> [!NOTE]
> No cross-provider fallback exists today. Callers import directly from the provider barrel. The full `sdk.ts` facade is only justified when a cross-provider operation exists; currently none do.

---

## Output Shape

Each provider function returns a stable shape that the caller (`core/`, `llm/`) consumes directly. There is no cross-provider normalization layer — the provider file is responsible for shaping its own output.

> [!NOTE]
> If a provider gets a new upstream source that requires a different response shape, the provider file normalizes internally before returning. Callers never see the raw upstream format.

---

## `caller.ts` — HTTP Transport Layer

`providers/caller.ts` is a shared HTTP client used by all provider subfolders. It is **not** the gate — it is infrastructure:

| Feature | Detail |
| :--- | :--- |
| Retry | Configurable retry count on network errors |
| Backoff | Exponential backoff between retries |
| Timeout | Per-request timeout to prevent hanging |
| No logic | Has zero knowledge of which provider, what data, or fallback decisions |

Provider files call `caller.ts` for their HTTP requests. `sdk.ts` calls provider files. The layers are strictly separate.

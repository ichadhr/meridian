# 4. External Folder Specification

The `providers/` directory contains all external I/O adapters, third-party API integrations, and blockchain SDK wrappers. Files in this folder are **strictly I/O-only and contain zero trading or agent business logic**.

> [!IMPORTANT]
> **Folder Behavior & Philosophy:**
> 1. **The Gate File Rule**: `providers/sdk.ts` is the **only file** imported from outside this folder. Provider subdirectories (`providers/okx/`, `providers/helius/`, etc.) are internal — never imported directly by `core/`, `llm/`, or `interfaces/`. If a provider gets an official npm package (e.g. `@okx/onchain-sdk`), only the files inside that provider's subfolder change. Nothing outside `providers/` ever knows.
> 2. **Fallback + Output Normalization**: Multiple providers can implement the same task (e.g. wallet balance: Helius, OKX, Solana RPC all expose this). `sdk.ts` owns the fallback chain — it tries the primary provider, catches failures or rate limits, and routes to the next. Critically, it also **normalizes the output** so the caller always receives the same field shape regardless of which provider actually ran.
> 3. **`caller.ts` is the HTTP transport layer**: Handles retry, backoff, and timeout for all providers. It has no knowledge of which provider or what data — purely transport concerns.

## Architecture Design: Two Layers

```
  core/ · llm/ · interfaces/
       │
       │  import { getWalletBalance, getTokenPrice } from "providers/sdk.ts"
       ▼
  ┌──────────────────────────────────┐
  │        providers/sdk.ts           │  ← Gate: fallback routing + output normalization
  │                                  │
  │  getWalletBalance(address)        │
  │    1. try helius → normalize      │
  │    2. on fail → try okx → norm.   │
  │    3. on fail → try RPC → norm.   │
  │    → always returns { sol, usdc, tokens[] }
  └──────────────┬───────────────────┘
                 │  uses
                 ▼
  ┌──────────────────────────────────┐
  │        providers/caller.ts        │  ← HTTP transport: retry, backoff, timeout
  └──────────────────────────────────┘
                 │  used by each provider
       ┌─────────┼──────────┬─────────────┬──────────┐
       ▼         ▼          ▼             ▼          ▼
  helius/    okx/       jupiter/     meteora/    solana/
  index.ts   index.ts   index.ts     index.ts    index.ts
  (Helius    (OKX       (Swap +      (DLMM SDK   (RPC connection,
   Enhanced   OnchainOS  Token        deploy,     account reads,
   Balances)  Risk API)  Info)        close, etc.) tx simulation)
```

## Provider Overlap — Same Task, Multiple Providers

Some tasks can be served by more than one provider. `sdk.ts` uses this redundancy for resilience:

| Task | Primary | Fallback 1 | Fallback 2 |
| :--- | :--- | :--- | :--- |
| Wallet token balances | Helius Enhanced API | OKX OnchainOS | Solana RPC (`getParsedAccountInfo`) |
| Token price feed | Jupiter Price API v3 | Helius | OKX pricing |
| Wallet risk score | OKX OnchainOS | *(none — optional gate)* | — |
| Account reads | Meteora SDK | Solana RPC (`getMultipleAccountsInfo`) | — |
| Tx simulation | Meteora SDK | Solana RPC (`simulateTransaction`) | — |
| Swap execution | Jupiter | *(no fallback — exclusive)* | — |
| DLMM pool operations | Meteora SDK | *(no fallback — exclusive)* | — |

> [!NOTE]
> For tasks with no fallback (swap, DLMM operations), `sdk.ts` still wraps them for consistent error handling and output normalization — it just doesn't reroute on failure.

## Output Normalization

Each provider returns data in its own shape. `sdk.ts` normalizes all responses before returning to the caller:

```
Helius response:  { nativeBalance: 2300000000, tokens: [{ mint, amount, decimals }] }
OKX response:     { tokenAssets: [{ chainIndex, tokenAddress, balance }] }
RPC response:     { value: [{ pubkey, account: { data } }] }

sdk.ts output:    { sol: 2.3, usdc: 100.0, tokens: [{ mint, symbol, amount, usdValue }] }
                  ← always this shape, regardless of which provider ran
```

The caller (`core/`, `llm/`) never needs to know which provider responded or what its raw format was.

## Naming Convention — `{functionName}{ProviderName}`

All provider functions must follow the pattern **`{functionName}{ProviderName}`** — camelCase, provider name capitalized as suffix. This makes the fallback chain in `sdk.ts` self-documenting: you can read which provider is primary and which is fallback just from the function names, without any comments.

```ts
// providers/helius/index.ts
export async function getBalancesHelius(address: string) { ... }

// providers/okx/index.ts
export async function getBalancesOkx(address: string) { ... }

// providers/sdk.ts  ← fallback chain is self-evident
export async function getWalletBalance(address: string) {
  try {
    return normalize(await getBalancesHelius(address));  // primary
  } catch {
    try {
      return normalize(await getBalancesOkx(address));   // fallback 1
    } catch {
      return normalize(await getBalancesRpc(address));   // fallback 2
    }
  }
}
```

| Provider suffix | Provider |
| :--- | :--- |
| `Helius` | Helius Enhanced API |
| `Okx` | OKX OnchainOS |
| `Solana` | Solana RPC node (direct connection) |
| `Jupiter` | Jupiter API |
| `Meteora` | Meteora DLMM SDK |
| `Hivemind` | HiveMind collective intelligence API |
| `Lpagent` | LPAgent / Agent Meridian API |

> [!IMPORTANT]
> Never export two functions with the same base name from the same provider file. If a provider has two different balance endpoints, name them distinctly: e.g. `getTokenBalancesHelius` vs `getNativeBalanceHelius`.

## `caller.ts` — HTTP Transport Layer

`providers/caller.ts` is a shared HTTP client used by all provider subfolders. It is **not** the gate — it is infrastructure:

| Feature | Detail |
| :--- | :--- |
| Retry | Configurable retry count on network errors |
| Backoff | Exponential backoff between retries |
| Timeout | Per-request timeout to prevent hanging |
| No logic | Has zero knowledge of which provider, what data, or fallback decisions |

Provider files call `caller.ts` for their HTTP requests. `sdk.ts` calls provider files. The layers are strictly separate.

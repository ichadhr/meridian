# 7. Utils Folder Specification

The `utils/` directory contains **shared low-level helpers and infrastructure utilities** used across all other folders. It has no knowledge of trading logic, agent roles, or platform specifics. Files here are pure utilities — stateless, reusable, and dependency-minimal.

> [!IMPORTANT]
> **Folder Behavior & Philosophy:**
> 1. **Zero Business Logic**: Utils must not import from `core/`, `llm/`, `interfaces/`, or `providers/`. They only use Node.js built-ins and minimal third-party packages (e.g. `dotenv`). If a utility needs to know about config or trading state, it belongs in another folder.
> 2. **No Circular Dependencies**: Because utils are imported by every other folder, they must never import from those folders. The dependency arrow is strictly one-way: all folders → `utils/`, never the reverse.
> 3. **Stateless by Default**: Utils functions should be pure or infrastructure-stateful (e.g. a logger that appends to a file is acceptable). They must not hold in-memory application state that could conflict across import contexts.

Shared logger with daily file rotation. Used by every other module for consistent structured output.

| :--- | :--- | :--- |
| `log` | `(category: string, message: string) => void` | General log function. Writes to console and appends to `logs/agent-YYYY-MM-DD.log`. Auto-detects level from category name (`error`, `warn`, `info`). Respects `LOG_LEVEL` env var. |

### [`utils/secure-env.ts`](file:///Users/ichadhr/Develop/node/meridian/utils/secure-env.ts)

Encryption/decryption utility for `.env` files. Protects sensitive keys (wallet private keys, API tokens) at rest using XOR-based cipher keyed from `.envrypt` key file or `ENVRYPT_KEY` env var.

| Function | Signature | Purpose |
| :--- | :--- | :--- |
| `loadEnv` | `(options?) => { encryptedKeys: string[] }` | Loads `.env`, identifies lines marked `# encrypted`, and decrypts their values into `process.env` using the encryption key. Called automatically at module import time. |
| `encryptEnvRaw` | `(options?) => { rawPath, outPath }` | Reads `.env.raw`, encrypts all `_KEY`, `SECRET`, `TOKEN`, `PRIVATE`, `MNEMONIC`, `PASSPHRASE` fields, and writes the encrypted result to `.env`. Used by the setup wizard. |
| `envryptEncrypt` | `(value, key) => string` | Low-level XOR + base64 encrypt. |
| `envryptDecrypt` | `(value, key) => string` | Low-level base64 + XOR decrypt. |

> [!NOTE]
> `loadEnv()` is called at the **bottom of the file** on import, so importing `utils/secure-env.ts` automatically decrypts and injects env values. This is intentional — it ensures secrets are available before any other module reads `process.env`.
